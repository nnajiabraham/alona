Field guide · November 2026

Meeting notes that never leave the device

This repository also holds a white-label app for health professionals. See the clinical guide. Test builds for every platform that builds today are on the 0.1.0 release page.

Alona records a meeting, transcribes it with a small speech model, and has a small language model write the notes. Both models run on the device. One codebase builds the web, macOS, iOS, and Android apps, and the web build is packaged for Windows and Linux.

Record

Microphone and a notes pad

A timer, a live waveform, and a pad for your own notes while the meeting runs. Type Markdown, or use the formatting buttons if you do not know it.

Transcribe

Speech to text, locally

Voice activity detection cuts the audio into speech, and each stretch is decoded as it is found.

Write

Notes from a small LLM

Summary, key points, decisions, action items, and open questions, led by what you wrote yourself.

Fit

A model tier per device

First launch checks memory and GPU, recommends a tier, and Settings lets you move to a lighter one.

How the pieces fit

System design

The app is built on Exact. The interface is one Contract file that each platform draws with its own controls. The logic is plain TypeScript in core/, the same on every host. Inference sits behind one JSON protocol, and each host answers it with its own engine.

Why one protocol

A host only has to answer nine requests. Prompts, chunking, tier rules, and storage are written once, so notes come out the same way everywhere.

Jobs are polled by id

The caller names each job. Starting a name twice returns the running job. An engine that restarted answers "unknown", and the pipeline starts that stage again.

Two writers, two sets of files

Your actions write meeting.json and notes.md. Only the pipeline writes stage.json, the transcript, and the AI notes. Neither can overwrite the other.

One model in memory

Speech and notes run one after the other. Loading one releases the other, and the engine unloads when the queue is empty.

From recording to notes

The pipeline

A meeting is a small state machine saved to disk. Once a second, while anything is unfinished, the app moves the oldest meeting forward by one step. Each step reads where the meeting is, asks the engine about that stage's job, and acts on the answer, so quitting the app mid-meeting loses nothing.

Short meetings

The transcript and your notes go to the model in one request when they fit the tier's budget: 3,000 tokens on Lite, 8,000 on Balanced, 24,000 on Quality.

Long meetings

The transcript is cut on segment boundaries, each part is reduced to topics, decisions, and action items, and one final request merges the parts.

No speech

A recording with no speech skips the notes model and says so.

What runs, and where

Models and tiers

The old app used Whisper large-v3-turbo, a 1.6 GB download. The new lineup is smaller per tier and picked by what the device can hold. Every file is pinned to a repository revision with its size and SHA-256 in core/artifacts.json, and a download only counts once its hash matches.

Lite notes are draft quality. In the measured runs the 0.8B model kept the right structure but sometimes gave a task to the wrong person. The transcripts carry no speaker labels yet, which makes ownership hard for any model.

Beyond record and write

The notes pad and the Mac features

The notes pad is one component, ui/notes-pad.contract, used by Alona and by the clinical app. The six Mac features below came from the original Swift app. Their logic is in core/ and one Swift file answers the parts only macOS can do.

Every platform

Formatting without Markdown

A toolbar over the pad: bold, italic, strikethrough, Title, Subtitle, Text, bullets, numbers, to-dos, quote, link, and a timestamp of the recording. Each button writes ordinary Markdown, so people who know it can just type. The bar scrolls sideways on a phone and stays above the keyboard.

macOS

Other people in the call

A Settings switch records the sound other apps play, such as the far side of a call, and mixes it with the microphone before transcription. macOS asks for System Audio Recording the first time. If the capture is silent, Settings says so.

macOS

Meeting detection

Alona notices a Zoom meeting or a call in a browser and shows a card on Home with a Record button. It can also send a notification. It never records by itself.

macOS

Menu bar item

Start and stop a recording, see the timer, and open the app from the menu bar. The app keeps running when its window is closed.

macOS

Your own folder

Settings chooses where meetings are kept. Each meeting is a plain folder with the audio, the transcript, and two Markdown files. If the folder goes missing, recording still works and the meetings move there when it returns.

macOS

Old recordings

"Find recordings" reads the Swift app's folders and imports them, with their dates and titles. The source is only read, never changed, and importing twice adds nothing.

The flows for these features run with stand-ins for the parts that need a permission prompt: a stand-in capture, a stand-in detector. What a person sees with the real prompts is recorded under Platform status.

The same foundations, a second app

Clinical app

Open the clinical guide for how the app looks under each brand, a visit step by step, and the workflows it covers.

A patient note-taking and transcription app for health professionals, on web, Android, and iOS. It shares Alona's core, pipeline, and engines. What differs is the note: the clinician picks a template, records a consultation, and gets a draft with that template's sections, written only from what was said. The draft stays marked as an AI draft until the clinician reviews it, and only a reviewed note can be copied or shared.

One file per tenant

A tenant is one typed file under tenants/: name, tagline, bundle id, thirteen colors in light and dark, wording, note templates, defaults, and feature switches. The types reject a missing field or a default template that does not exist.

Checked before it builds

tenant.mjs check catches what types cannot: text contrast under 4.5 to 1, white on the accent under 3 to 1, duplicate template ids, a malformed bundle id, a missing icon. Each error names the field and the fix.

Edits belong to the clinician

The model's draft and the clinician's edits are separate files. The pipeline never overwrites an edit, and "Write again" asks before replacing one.

No compliance claim

The app says what it does: audio, transcripts, and notes are processed and stored on the device. Whether that meets a regulation is for the owner to establish before real patients.

On real models the Lite tier's clinical draft passed the format check and added nothing that was not said, but it was a poor note: it copied guidance sentences and repeated the history under the impression. Treat Lite drafts as a starting point until accuracy is measured on real consultations.

Real models, real numbers

Measured results

These come from repeatable checks that run the built app on real models with a 53-second spoken meeting (three synthetic voices) and compare the transcript with the script that was spoken. Synthetic speech is easier than a real room, so read the word error rate as a floor.

Memory on macOS is the app's physical footprint, the figure Activity Monitor shows. It leaves out the model file itself, which is memory-mapped: 0.5 GB on Lite, 1.3 GB on Balanced, and 5.7 GB on Quality stay in the system's file cache while the notes model runs. Memory in the browser is resident size, which runs higher than footprint.

Memory over time

A leak shows as a figure that keeps climbing. These two checks follow memory through a long recording and through many meetings in one process.

Moss on stone

Brand guide

Alona should feel like a quiet notebook. The palette is moss and lichen green on warm stone gray, with clay for recording and anything that needs attention. Controls stay the platform's own, so the app reads as native on each device, and brand color goes on the accent and on the app's own surfaces.

Color rules

Moss means go or done. Clay means recording or a problem. Ochre marks a notice, such as the demo engine. Never use color alone: each state also has words.

Type

The app uses each platform's system font and its named sizes (large title, headline, footnote), so text follows the person's accessibility size. This guide uses Schibsted Grotesk and Inter.

Shape and space

Cards have 14 to 18 px corners and no shadows. One column on a phone, a centered 720 px column on wide screens. One main action per screen, filled in moss.

Voice

Plain and specific. Say what happens ("Stop and write notes"), where things are ("Saved on this device"), and why something cannot be done, with the number.

The tokens live in app.tamber. Each has a light and a dark value, and bun exact.mjs tamber check . verifies contrast for the text pairs.

From clone to a running app

Developer onboarding

1. Tools

  • macOS on Apple silicon, with Xcode. Exact's Apple hosts ask for Xcode 27.1. On Xcode 26.1 the macOS host builds after the patches in step 2, and the iOS host does not build.
  • Rust through rustup, and Bun 1.4.2. Node is not needed.
  • Google Chrome, for the web tests and the web real-model check.
  • For Android: the Android SDK with platform 37.2, build-tools 37.0.0, an NDK, and JDK 17 or newer.

2. Set up

# Exact has no packaged CLI. Apps use a checkout beside them.
git clone https://github.com/expo/exact.git ../exact
git -C ../exact checkout 3baa28ffa5e2598f2eca2ff5d830fa2b444e741f
bun ../exact/scripts/exact.mjs setup            # toolchains, a few minutes

# Only on Xcode older than 27.1: let Exact's Swift host compile.
git -C ../exact apply "$PWD/tools/patches/exact-3baa28f-xcode26.patch"
# For recording other apps' audio on macOS: a permission row Exact lacks.
git -C ../exact apply "$PWD/tools/patches/exact-3baa28f-audio-capture.patch"

bun install
bun exact.mjs update                            # point exact.mjs at your checkout
tools/fetch-apple-frameworks.sh                 # sherpa-onnx, ONNX Runtime, llama.cpp
bun tools/build-web-engine.mjs                  # bundle the web worker

# Only for Android: build the inference runtimes, and patch Exact to find them.
python3 tools/build-android-runtimes.py         # llama.cpp with the NDK, sherpa-onnx's AAR
eval "$(sh tools/prepare-android-exact.sh)"     # sets EXACT and ALONA_ANDROID_MAVEN

For the Windows and Linux packages, bun tools/build-desktop.mjs builds the web app, wraps it in the Electron shell under desktop/, and writes the two .deb files and the Windows installer. It runs on a Mac.

3. Run it

bun exact.mjs web          # the web app, rebuilt on save
bun exact.mjs mac --run    # the macOS app
bun exact.mjs android      # build and install on the emulator or phone in ANDROID_SERIAL
bun tools/tenant.mjs build default web     # the clinical app, for one tenant

bun tools/release.mjs build                # every platform's package into release/
bun tools/release.mjs publish              # a GitHub release with notes and checksums

How to change the models

Edit the spec list in tools/pin-models.mjs and run it. It writes the files, sizes, and hashes to core/artifacts.json. Then name the artifact under a tier and host in core/models.ts. A host is listed under a model only after that host's engine has run it end to end.

How to add an engine for a host

Answer the nine requests in core/engine.ts from that host's native module, with modules/apple/Engine.swift as the reference. Start jobs by the id the caller gives, answer "unknown" for an id you do not have, verify downloads before reporting a model installed, keep one model in memory, and check for cancel while working. Then add the host's artifacts to core/models.ts.

Contract habits worth knowing
  • A screen is a route. A value never changes in place, and nothing runs because a value changed: an event runs an action.
  • The data module has no clock and no randomness. Time comes in as an argument from the view.
  • Contract test files cannot grant the microphone permission. Scripted drives can, which is why recording flows live in tools/flows.mjs.
  • A drive refuses a build older than its sources. Rebuild with the host's verb when it says so.
What is not done

Open gaps

Blocked

iOS

Xcode 27.1 is installed but not licensed on the build machine. Nothing about iOS has been compiled or run, for Alona or for the clinical app.

Unverified

The Mac features, live

System audio capture, Zoom and Meet detection, and notifications each sit behind a macOS permission prompt. Their flows pass with stand-ins. Nobody has yet allowed the prompts and watched the real thing work. The checklist is in docs/rewrite/mac-features.md.

Unverified

Real rooms and real microphones

Every accuracy figure comes from synthetic voices fed in as a file or a fake microphone. No hardware microphone and no real meeting has been run on any platform.

Unverified

Windows, and Linux on a real GPU

The Windows installer has never been run. The Linux package has only run in a container without a GPU, where it falls back to samples. Both packages are unsigned and carry the Lite tier only.

Unverified

A physical Android phone

Real models ran on an emulator with 8 GB of memory. Speed, heat, and memory on a real phone are not measured.

Unexplained

A memory peak after Stop on macOS

Between Stop and the finished notes, the app's footprint peaked near 1.2 GB in the long-recording check, with or without system audio. It returns to about 100 MB after. The source is not identified.

Known bug

Toolbar at the largest text size

At phone width and the largest accessibility text size, with the page scrolled, the sticky toolbar overlaps the link-address row in My notes.

Unmeasured

Long meetings and note quality

A 10-minute recording has been run through real models on macOS. No hour-long recording has, and no eval set scores the quality of the notes. Lite notes are draft quality.

Owner decisions

Clinical use

Before real patients: a regulatory review, accuracy measured on real consultations, whether to screen the patient reference for identifiers, and whether audio is deleted after review.

Known limit

Speaker labels

Transcripts have timestamps but no speakers. Diarization models exist for the runtimes in use and are not wired in.

Known limit

Unsigned builds

Every package is unsigned or ad-hoc signed. macOS, Windows, and Android will warn on install until the owner signs them.
